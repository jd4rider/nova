## Audit

- Nova GUI is a real macOS AppKit window with a CoreGraphics framebuffer and
  polled input; it had no native-view handoff.
- FFI supports scalar/String/Unit values and opaque integer handles, not
  callbacks or raw Objective-C objects.
- No WebKit, Chromium or WebCore code existed.
- `http_get` shells out to curl; no browser URL/HTTP/storage layer exists.
- Boxes can read/resolve/pack but not publish.
- Qualified imported struct signatures are rejected by codegen
  (`BROWSER-COMP-01`).

## Slice delivered

- `runtime/webkit.m`: thin WKWebView host with opaque handles, navigation
  delegate, polled state, DOM text, title/URL/error, snapshot, and fail-closed
  scheme policy. No browser chrome or layout logic.
- `runtime/gui.m`: `nova_gui_native_view()` opaque content-view handoff.
- `libraries/nova-webview`: Nova binding, `wv_*` flat-namespace API.
- `browser/engine-api`: engine-neutral status/capability contract.
- `browser/engines/webkit`: WebKit adapter; no WebCore delegation.
- `browser/app`: native Nova GUI shell with Gruvbox chrome, WKWebView page area,
  buttons/shortcuts and lifecycle cleanup.
- `browser/fixtures/start.html`: offline trusted fixture with CSS and page
  JavaScript.
- `browser/tests/lifecycle`: headless WKWebView lifecycle project.
- `examples/nova-tool`: conditional `webkit.m` compile and `-framework WebKit`
  link only when `nova_webview_` is referenced.

## Debugging encountered

1. Qualified struct literals (`contract.PageStatus { ... }`) were rejected by
   this parser; construction moved into contract helper functions.
2. Flat namespace collision between webview and contract states; the binding
   API was prefixed `wv_*`.
3. Imported qualified struct return/parameter signatures are unsupported by
   codegen; the adapter exposes primitive accessors and the compiler gap is
   tracked as `BROWSER-COMP-01`.
4. `WKWebView.title` needed a DOM fallback after `loadHTMLString`.
5. `loadHTMLString` does not create fixture back/forward history; this is
   documented and the test now checks the no-history path honestly.

## Crash-report identification (owner-supplied 03:40 trace)

The owner pasted the 03:40:19 report: `SIGABRT` with
`-[NovaGuiView validAttributesForMarkedText]: unrecognized selector`, thrown by
`-[NSTextInputContext initWithClient:]` inside `-[NSApplication updateWindows]`
on the first run-loop pass. AppKit builds the input context as soon as the view
becomes first responder, so a view that declares `NSTextInputClient` without the
whole protocol crashes before any key arrives. This is the defect the first IME
change introduced and the reason 0.6.0 completed the protocol — it is *not* the
03:29 stack overflow, which has a different fault (SP below the 8 MB stack with
only three Nova frames).

Checked on the installed 0.7.0: `nm -m` shows
`-[NovaGuiView validAttributesForMarkedText]` in `__text`, no `nova-browser`
crash report exists after 03:40, and an AUTOCLOSE launch reaches
`state=ready`. `tests/ime.sh` drives the same view through the input-client
entry points, so a missing method fails the test step.

## 0.7.1 — grapheme-aware address editing (WB-03.001.a)

Found that the bundled self-hosted compiler has no `graphemes()` method: the
runtime exports `nova_string_graphemes` and the docs describe the method, but
method dispatch in `libraries/nova-codegen/src/llvm.nova` never declares or
calls it, so `text.graphemes()` fails with "unsupported method graphemes". Rather
than rebuild the compiler for a browser slice, segmentation now lives in
`browser/address`: scalars come from `chars()`, code points are decoded from each
element's UTF-8 bytes, and the runtime splitter's rule set (combining marks,
variation selectors, keycaps, skin tones, regional-indicator pairs, ZWJ) groups
them into clusters.

The address model exposes `cluster_starts`, `cluster_count`, `char_left`,
`char_right` and `snap`. The browser uses them for Left/Right,
Backspace/Delete, click carets (candidates are cluster boundaries only, still a
single width-accumulating pass) and word snapping, so one keystroke cannot leave
the caret inside "e"+U+0301, "👨‍👩‍👧", "🇺🇸" or "👍🏽".

18 new address assertions (56 PASS total): accent is 2 scalars but 1 cluster,
family 5 scalars / 1 cluster, flag and thumb 2 scalars and removed whole,
Backspace and Delete both remove the whole cluster, ASCII still steps one,
`snap` moves an interior offset back to the cluster start, and insertion at 0
preserves the text.

Regression: history 72/0, tabs 5/5, IME 4/4, downloads 5120 bytes, lifecycle
25/0, bench 120 avg=4ms worst=174ms fx_step_2000=4ms stack=13KB/8176KB.
Installed 0.7.1, plist 0.7.1, signature valid, launch 1190 ms to state=ready.

## 0.7.3 — download pause/resume (WB-04.002)

Downloads could be cancelled or revealed but not stopped and continued. A
running shelf row now pauses on click: the partial file stays, and WebKit's
`cancel:` completion supplies resume data. Clicking the paused row (or a failed
one that carries resume data) calls `WKWebView.resumeDownloadFromResumeData:`,
whose delegate re-entry reuses the entry's existing destination path, so the
transfer continues into the same file rather than a `-1` sibling. Rows that
cannot resume say so instead of silently restarting from zero.

`browser/tests/downloads.sh` now serves 51,200 bytes from a Range-capable
loopback server with `ETag`/`Last-Modified` and trickles the body, so the probe
can pause mid-transfer. Observed: `paused at 10240`, `resumable=1`, `resumed`,
`state=done bytes=51200`, file size 51,200; a second run into the same directory
wrote `nova-fixture-1.bin`, which covers the collision policy.

Two things surfaced. First, the initial pause returned no resume data because
the origin sent no validator; WebKit only produces resume data when the server
supports ranges, so the test server was fixed and the shelf now reports
"cannot resume" when that happens. Second, `WKDownload.webView` is nil for
downloads that began as a main-frame navigation, so the entry keeps the
`WKWebView` passed to the delegate (strong, released on finish).

Regression set green: accessibility 11/11, address failures=0, history

`runtime/speech.m` wraps AVSpeechSynthesizer as polled state, and nova-tool
compiles it only for programs whose IR asks for `nova_speech_*`, linking
AVFoundation. The speaker button and Cmd+Shift+L read the page text WebKit
returns; Cmd+Shift+V cycles installed English voices and settings.tsv keeps the
choice. Verified with a fixture: 948 chars, a default English voice, speaking=1.
Audio itself is unverified and muted in tests. Kokoro stays a seam: no model or
ONNX runtime is bundled, and the UI says so instead of substituting silently.

The address suggestion list used to be hidden below the 118 px chrome band,
because chrome is the WebView's parent and paints under it. gui.overlay now
registers rectangles that the host copies from the frame into a transparent
view above the page, with hit testing returning nil outside them and clicks
re-entering the Nova queue inside them. Trace: `overlay rects=1 top=1`.

Build clean, accessibility 17/17 (counts 11/13/14), all suites green, bench
7 ms avg, installed 0.8.6.

## 0.8.7 — reader panel, floating rail, voice model

The speaker now opens a panel instead of only starting speech: read, pause,
resume, stop, speed in 25% steps and the installed English voices, all painted
above the page through gui.overlay. Cmd+Shift+L still reads directly and
Cmd+Shift+Space pauses. Speed persists as `voice_rate`.

The rail's name panel stopped taking width from the page. It is an overlay too,
so hovering the rail no longer reflows the document; the page keeps `page_left`
and the panel is copied above the WebView.

A download row fetches the Kokoro model with curl in a pty slot, samples the
`.part` file for progress, and promotes it only after the size check. The model
is installed in the profile; the neural runtime is not bundled, so `backend`
stays `system` and the notice says why. That distinction was tested: a stub
model installs and is detected, and still reports the system backend.

The first version of the panel was unusable: every voice lookup re-sorted all
installed voices, so a panel frame took seconds. Caching the sorted list in the
host and adding a native English count brought the run back to ~1.1 s.

## 0.8.8 — Kokoro without pretending

Kokoro needs three things: a model, a synthesizer, and patience. The model
could already be downloaded; this adds the synthesizer as a command
(`<cmd> <text-file> <out.wav>`) and the patience as UI: a wheel, a moving bar
and the elapsed seconds in the panel, plus the same wheel in the toolbar when
the panel is closed.

Built-in voices remain the default. Kokoro appears in the voice list only when
the model is installed, marked `needs a synthesizer` until a command is found.
Picking it then prints why and reads with Albert, rather than switching engines
silently or failing after a long wait.

The phase report comes from the child process, not a timer: synthesizing while
it runs, playing while afplay does, failed with the command's last line. Pause
is SIGSTOP/SIGCONT on whichever child is running. That is as far as this can be
verified without a real Kokoro install: the tests use a stub command, so the
wheel is proven, the voice is not.

## 0.8.9 — window buttons on the chrome's rows

The traffic lights are AppKit's own: the window server routes their clicks,
VoiceOver reads them, and the green button keeps its zoom menu. What was wrong
was their place. A full-size content view pins them to the window's top edge,
so with vertical tabs they floated above the toolbar instead of sitting in it.

`nova_gui_place_traffic_lights` moves the three frames onto the row the app is
drawing: the tab strip's centre (y=23) when tabs are horizontal, the toolbar's
centre (y=29) when they are vertical or collapsed to the rail. It runs every
frame because AppKit restores the default frames on resize and when full screen
exits. The tests read the placement from the GUI trace, since a framebuffer
snapshot cannot include AppKit-drawn buttons.
