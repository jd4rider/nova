## Slice delivered — 0.9.8 find in page and page zoom

- `runtime/webkit.m`: `nova_webview_find` calls
  `WKWebView findString:withConfiguration:completionHandler:` with wrap and
  backwards options and stores a polled result (0 cleared, 1 found, 2 not found,
  3 searching) on the view entry. `nova_webview_set_zoom`/`nova_webview_zoom`
  wrap `pageZoom`, clamped to 50–300%. The host key monitor now queues Cmd+F,
  Cmd+G (with Shift), Cmd+=, Cmd+- and Cmd+0, so they work while WebKit owns
  focus.
- `libraries/nova-webview` and the WebKit adapter expose `wv_find`,
  `wv_find_state`, `wv_set_zoom`, `wv_zoom` as `find_text`, `find_state`,
  `set_zoom`, `zoom`.
- `browser/app/src/main.nova`: Store gains `find_open`, `find_text`,
  `find_found`. A 320x34 find bar draws over the page top right and registers
  with `gui.overlay`; the close control, hover, text cursor and click handling
  are the same patterns the bookmarks panel uses. Typing searches on every
  character, Enter/Shift+Enter and Cmd+G/Cmd+Shift+G step matches, Escape clears
  the selection and returns focus to the page, Backspace edits the query through
  `address_edit.slice_chars`. Cmd+=/Cmd+- step 10% and Cmd+0 resets, each with a
  notice. The frame loop polls the find result and includes the bar in the dirty
  signature.
- `browser/tests/find.sh`: loopback fixture, requires
  `zoom=150 reset=100 hit=1 miss=2 cleared=0 panel=320x34` and the seeded bar
  geometry.

## Decisions

- No match count. `WKFindResult` reports only `matchFound`; counting DOM text
  would disagree with WebKit's own matching, so the bar says Found / No matches.
- Zoom uses `pageZoom`, not framebuffer scaling, so layout follows the scale.
  It is per tab and resets on a new tab; per-host persistence is left open.
- Cmd+F is forwarded rather than left to the page, matching Chrome, but the bar
  does not steal Cmd+A or other editing chords from the address field.

## Follow-up — 0.9.9 per-host zoom and find bar accessibility

- Zoom writes `zoom:<host>` through `setting_with` and `stored_zoom` re-applies
  it when a navigation settles on a new URL; Cmd+0 stores 100%. The host comes
  from `library.host_of`, so a port or path does not split a site's zoom.
- `ax_find` publishes the query as an `AXTextField` (label "Find in page") and
  the × as a named button ("Close find bar"), placed from the same `find_box`
  geometry the mouse uses.
- `tests/find.sh` extended to 11 checks: the AX dump names both controls, a run
  with `NOVA_BROWSER_ZOOM_SET=150` writes the setting, and a second launch of
  the same profile reads back `applied=150 stored=150`. Accessibility stayed
  17/17 because the base chrome gained no controls.

## Follow-up — 0.9.10 pages follow the chrome appearance

- The owner asked for dark pages after 0.9.9. `gui.set_appearance` already set
  the app/window appearance, but an offscreen or newly detached WKWebView does
  not inherit it, so pages could still answer `prefers-color-scheme: light`.
- Added `nova_webview_set_appearance_all` (dark/light), exposed as
  `wv_set_appearance` and `engine.apply_page_appearance`. It runs before the
  first load, at startup, and on every theme change, so all tabs switch
  together.
- Name collision: Nova links module functions into one namespace, so
  `engine.set_appearance` clashed with `gui.set_appearance`; renamed to
  `apply_page_appearance`.
- `tests/dark.sh` requires `theme=gruvbox light=0 media=1` and
  `theme=light light=1 media=0` from a real loopback page.

## Follow-up — 0.9.11 private tabs

- `nova_webview_create_store` now takes a `private` flag; `--private` and
  Cmd+Shift+N create a view whose configuration uses
  `WKWebsiteDataStore.nonPersistentDataStore`. `nova_webview_store_persistent`
  reports WebKit's own answer for the tab.
- Visit recording moved into `record_visit`, which refuses private tabs, the
  fixture and a profile with history off. `save_session` skips private tabs and
  returns without writing when there are none, so a private-only quit cannot
  erase the previous session. Favicon caching is skipped while the active tab
  is private.
- The strip and the accessibility name prefix private tabs with `Private ·`.
- `tests/private.sh`: private run reports `flag=1 persistent=0 visits=0` and
  leaves no session/history line; the normal control run reports `flag=0
  persistent=1 visits=1` and saves the URL. 5/5.

## Follow-up — 0.9.12 saved logins

- The runtime injects a submit listener and a `novaLogin` message bridge; a
  normal tab's submitted password form lands on the entry, and a private view
  is refused at the sink. `nova_webview_fill_login` fills the page's own form
  through property setters plus input/change events, and refuses when the
  password field already has a value, so a site's own manager is not
  overwritten and Nova never submits.
- Storage is the login keychain, service `dev.nova.browser.login`, one
  generic-password item per host whose value is `escape(user)` + tab +
  `escape(password)`. `browser/login` reads and writes it; `--forget-login`
  removes one. The runtime now links `Security`, which is why `nova-tool` had to
  be rebuilt from `bootstrap/nova` before the browser would link.
- The browser stores a captured login after navigation and fills a host once
  per URL, showing `Saved login for <host>`; private tabs skip both.
- `tests/login.sh`: normal run reports `captured=1 saved=1 filled=1
  fields=ada|hunter2`, the probe deletes its item, and the private control run
  reports `captured=0 ... filled=0`. 3/3.

## Follow-up — 0.9.13 Chrome password import

- `import_chrome_logins` uses `sqlite3` on an immutable `Login Data` snapshot
  and selects `hex(password_value)`, so the ciphertext survives the text pipe.
  `login.decrypt` calls the runtime's `nova_chrome_decrypt`: v10 prefix stripped,
  PBKDF2-HMAC-SHA1 (saltysalt, 1003, 16 bytes) over Chrome's Safe Storage key,
  AES-128-CBC with a sixteen-space IV, PKCS#7 verified and stripped. Any
  unexpected prefix, size or padding returns empty.
- The key comes from `nova_chrome_key`: env overrides for tests, otherwise the
  `Chrome Safe Storage` generic-password item (macOS may ask). A missing key
  prints `chrome key locked` and the import adds nothing.
- `apply_imported_logins` skips hosts Nova already has, so an import never
  overwrites a credential changed in Nova; a dry run counts without writing.
  The CLI line now ends with `logins=N` and Cmd+Shift+I mentions saved logins.
- `tests/chrome-logins.sh` builds a real Chrome-shaped profile with a v10 row
  encrypted from a known key: `logins=1`, autofill `fields=ada|hunter2`, second
  import `logins=0`, locked import `logins=0` with the lock message. 6/6.
