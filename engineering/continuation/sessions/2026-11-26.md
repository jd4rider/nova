## Generic functions (COMP-01.04 subset)

- Added `nt_monomorphize`: explicit single-parameter generic functions
  (`fn id<T>(x: T) -> T` called as `id<Int>(7)`) are instantiated before sema and
  codegen. The detector only treats `<...>` before `(` as a type parameter, so
  `List<String>` parameters are not misclassified.

## Traits, closures and CI (COMP-01.04)

- Lexer/parser: `trait` keyword; AST kinds `ak_trait`, `ak_sig`, `ak_closure`.
  Parses `trait Name { fn method(self) -> T }`, `impl Trait for Type { ... }`,
  inherent `impl Type { ... }`, `|x: Int| expr`, block bodies and optional
  `-> Type`; the renderer covers trait, signature, impl and closure nodes.
- Sema: collects methods as `Type.method`, requires the declared trait signature,
  rejects a missing method with `E0201`, checks trait impls only on non-generic
  types, and types closures/function values as `fn(...) -> ...`. A single-file
  `build` bypasses body sema, so trait diagnostics are tested through
  `NOVA_TOOL=sema-ast`.
- Codegen: methods lower to `Type.method` with `self` as the first value
  parameter and concrete receivers dispatch at compile time. Closures lift to
  `__closure_<node>` functions and named function values to
  `__fnref_<index>_<node>` thunks; both use `%nova.fn = { fn, env }`. Captures
  are copied by value. Higher-order calls, returned closures, nested captures
  and function values work. A regression where `cg_for_list` passed stale state
  (undefined `%t161`) was fixed by threading the evaluated state.
- Tests: `cli.sh` 33/0 with generic, closure, trait and missing-trait-method
  cases; `parser.sh` 54/0 with trait/impl/closure AST fixtures.
