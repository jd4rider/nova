# Engine session — 2026-11-26

## Directive

Owner adopted `Nova Engine — Master Engineering Directive` as the official
specification: a native 2D/3D engine and Unity-inspired editor in Nova, with
compiled Nova, NovaScript and visual scripting as first-class, interoperable
gameplay systems. macOS ARM64 first; no wrapper engine; audit before building.

## What was done

1. **Audit.** Read root `AGENTS.md`, `ROADMAP.md`, the continuation protocol,
   the browser state/tasks/evidence, and the existing engine assets:
   `libraries/nova-engine/{scene,render}.nova`, `libraries/nova-game/{engine,
   physics}.nova`, `examples/{physics-lab,scene-gui}`. Confirmed the compiler is
   self-hosted and Rust-free, and that no graphics device layer exists.
2. **Baseline.** `physics-lab` failed 2 of 24 with `scene-tick` write loss;
   `scene-gui` failed to build on `BROWSER-COMP-01`. Recorded both instead of
   assuming green.
3. **ENG-01.00 fix.** `scene_tick` and the three setters now return a rebuilt
   `Scene` carrying the mutated columns. Enumeration order, collision core and
   gameplay behaviour are unchanged. `physics-lab` is 22/0.
4. **ENG-01.001–003.** Added `math.nova` (Q16.16, sqrt, trig, Vec2/Vec3/Quat/
   Mat4/Transform, perspective/ortho/look-at) and `core.nova` (generational
   `EntityId`/`EntityPool`, `Clock`/`Tick` fixed timestep). Added
   `examples/engine-lab` with a headless demo and 21 acceptance tests.
5. **Persistent state.** Created this directory and registered it in root
   `AGENTS.md`.

## Decisions made

- ADR-ENG-001: fixed-point simulation math because Float codegen is unverified
  and determinism matters.
- ADR-ENG-002: generational handles; no raw indices reach scripts or editor.
- ADR-ENG-003: reuse the working integer physics/scene substrate, migrate later.
- ADR-ENG-004: runtime never imports editor; headless harness required.
- ADR-ENG-005: integer-microsecond fixed timestep with recorded stall drops.

## Failures and corrections during the session

- First test run failed all 21 cases on `assert_eq` being unavailable in the
  `nova test` build; replaced it with a local `same` helper that panics with
  values.
- `fx_div` truncated, producing ~0.8% error at an 800 px ortho edge; changed it
  to round to nearest and used documented edge tolerances.
- Test-authoring errors fixed rather than loosened: 60 × 8,333 µs is exactly
  30 steps; far-clip Z is clip-space (100), not NDC; two trig inputs used `*`
  instead of `fx_mul` and produced a 49000-iteration range reduction.

## Second slice (same day)

1. **ENG-01.004/005/006.** Added `libraries/nova-engine/src/world.nova`:
   concrete component columns behind generational handles, deferred spawn and
   destroy flushed at step end, gravity/integration, interpolation and a
   deterministic trace hash. Engine suite is 26/0; the 600-step trace matches
   across runs; `engine.sh` and physics-lab (22/0) stay green.
2. **Float codegen.** `Float` now lowers to `double`: literals, parameters,
   `let`/`var`, assignment, `fadd/fsub/fmul/fdiv/frem` and `fcmp`. Added
   `codegen-float.nova`; the IR compiles and exits 7, suite 255/0. Float through
   `nova build`/sema and wasm is still unverified, so simulation stays Q16.16.
3. **BROWSER-COMP-01.** `cg_unqualified` strips the module qualifier at type
   lookup, and signatures store declared names. `scene-gui` then hit
   `gui.min` being claimed by the `List.min()` builtin; the builtin now requires
   zero arguments and a list receiver. `scene-gui` builds with the fresh
   compiler. Stage-0 `bootstrap/nova` was deliberately not replaced: that needs
   the BOOT-02 self-build gate.
4. **Nova Engine Studio.** Added `VERSION`, `icon.html` and
   `install-macos.sh` to `examples/scene-gui`; installed
   `/Applications/Nova Engine Studio.app` 0.1.0 (`dev.nova.engine.studio`),
   ad-hoc signed, 1024 px icon, and verified a 2400×1520 render from the
   installed binary. This is the phase 0 scene/inspector surface, not ENG-04.

Mistakes caught by tests, not papered over: Float `+` fell through the opcode
chain to an error; `List.min()` intercepted `gui.min(a, b)`; `gui.save_png`
returned `saved=false` because the output directory did not exist.

## Fourth slice

1. **ENG-02.002 Metal triangle.** Added `runtime/metal.m` and
   `libraries/nova-render/src/metal.nova`, plus `examples/metal-lab` and its
   script. The compiler driver now detects `@nova_metal_` and links MetalKit
   only for programs that use it. Verified: 3 frames, resize from 900×640 to
   640×480, two PNG captures (1800×1280 and 1280×960), clean shutdown, exit 0.
2. Fixes driven by the rendered output, not assumptions: packed vertex layout
   (`float4` alignment had corrupted the first frame), MTKView delegate instead
   of manual drawable presentation, and window close/release ownership during
   teardown.
3. **Reported teardown crash.** The owner supplied the crash report from the
   pre-fix binary: `nova_metal_shutdown + 156` → `objc_autoreleasePoolPop` →
   `objc_release`. Root cause was the window double-release fixed above. Added
   `examples/metal-lab/tests/shutdown.sh`; 5/5 complete cycles exit 0 on the
   rebuilt binary, plus the single acceptance run.
4. **Editor UX preference.** The owner asked for Unity-first UI with
   Godot/GDevelop/Defold as local references only. Accepted ADR-ENG-009: left
   hierarchy, centre scene/game with play/pause/step, right inspector, bottom
   project/console, neutral dark theme, real runtime state, no mock editor.
   Studio 0.1.0 remains phase 0; the shell is ENG-04.

## Fifth slice

1. **ENG-02.003 textured quad.** `runtime/metal.m` now decodes a PNG with
   ImageIO, uploads a BGRA8 texture, and samples it through a UV attribute and
   a linear clamp-to-edge sampler. A 64×64 red/green/blue/yellow checker is the
   checked-in fixture. The ABI stays Int handles, Ints and strings: one texture
   slot, no Metal objects or pointers across the boundary. A white 1×1 fallback
   keeps drawing valid before a load.
2. Acceptance samples actual capture pixels through `sips` and uncompressed
   BMP, so it needs no Python or image library. First run caught a real defect:
   the top-left quadrant read blue because the upload flipped an already
   top-down `CGBitmapContext`; removing the flip made all four quadrants match
   within ±12 at 1800×1280 and 1280×960. Shutdown stays 5/5 clean.
3. Studio stays phase 0. Next is depth and a 3D cube (ENG-02.004), then the
   Unity-first shell (ENG-04.002).

## Sixth slice

1. **ENG-02.004 depth and cube.** Added a Depth32Float attachment, a
   less-than/write depth state, a 36-vertex six-colour cube, and a geometry
   selector on the existing scalar ABI. The camera is built in `math.nova` and
   arrives as 16 Q16.16 Ints; the host transposes them for Metal and the shader
   remaps z to Metal's [0,1] clip range.
2. Axis-aligned face sampling proves the result, not just the exit code: +Z
   blue, +Y green and +X orange pass at both drawable sizes; hidden -Z magenta
   and -X olive do not appear. `metal.sh` and `shutdown.sh` remain green;
   `cube.sh` is the new acceptance.
3. Two defects caught before closure: the first cube passed `fx(50)` as 50
   radians to a projection that expects radians, producing an enormous zoom
   (fixed by converting degrees); and `math.nova`'s [-1,1] projection needed
   the Metal [0,1] z remap. Both are documented in `EVIDENCE.md`; no assertion
   was loosened.
4. ENG-02 is closed. Next is ENG-04.002, the Unity-first shell against real
   `world.nova` state.
