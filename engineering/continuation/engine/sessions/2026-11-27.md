# 2026-11-27 — Inspector edits and undo (ENG-04.003)

Starting point: Studio 0.3.0 had the offscreen Metal viewport, real hierarchy
selection, a live inspector and console, but the transform rows were read-only.

1. **Editable transform rows.** Position, Rotation and Scale are now inline
   fields. Clicking a row uses the same inspector hit test as any other mouse
   action; composed text arrives through `event_text`/`typed_text`. Enter parses
   three or four comma-separated decimals into Q16.16 and commits through
   `world_set_position/rotation/scale`; Escape cancels; invalid input keeps the
   field active.
2. **Editor-only command history.** Each commit stores
   `EditCommand { entity, field, before, after }`. A 16-entry stack in `App`
   replays the before or after value; a new edit truncates redo. Undo/Redo
   buttons and ⌘Z/⇧⌘Z share the same path. The runtime World has no undo state.
3. **Capture acceptance.** `tests/shell.sh` now captures base, edit, undo and
   redo. It checks `history=1/1 → 0/1 → 1/1` and the printed Position, then
   compares only the Scene viewport crop so inspector chrome cannot mask a
   world change. Undo must equal the base crop; edit must differ; redo must
   equal the edit crop.
4. **Language snag.** The first build rejected `app = edit_commit(app)` in
   `handle_mouse_down` because function parameters are immutable. A local
   `var app = app` fixes the click-commit path; no runtime or GUI-host change
   was needed.
5. **Shipped.** Studio 0.4.0 installed at `/Applications/Nova Engine Studio.app`,
   signature verified. Installed base/game/edit/undo/redo captures are
   byte-identical to the local test captures.

Limits: history is per-session and single-field; no multi-select, grouped
commands, gizmo, persisted undo, prefab or scene save/load. The editor camera is
still fixed. Next was ENG-04.004, dockable panels.

# 2026-11-27 — Persisted panels and Game Camera (ENG-04.004 / ENG-11.004)

Starting point: Studio 0.4.0 had editable transforms, undo/redo, a Metal
viewport and a fixed editor camera; Game was Scene with overlays hidden.

1. **Panel state.** Added `Panels` to `App`: left/right/drawer sizes, visibility
   flags, drag origin/start and a layout path. `layout.txt` stores the values
   under Application Support; `NOVA_SCENE_LAYOUT` isolates tests. Missing values
   clamp to the previous 252/304/196 defaults with all panels visible.
2. **Real resize and visibility.** Splitters use the same mouse-down/drag/up
   path as the window; menu-bar `Hier`/`Insp`/`Draw` chips toggle panels through
   their hit test. Hiding Inspector cancels its active field but never clears
   the World or selection. Save happens on mouse-up or chip toggle.
3. **Game Camera.** The demo world adds tag-6 `Game Camera` at `(0, 2.60,
   7.50)` with a -12° pitch. Game derives eye/forward/up from its World
   position and rotation; Scene keeps the fixed editor camera. Tag 6 is skipped
   from its own Game render, and the inspector can move or rotate it.
4. **Acceptance.** `shell.sh` now expects seven entities, compares Scene and
   Game viewport crops, selects the camera and moves it to `(0, 2.20, 4.00)` to
   require a changed Game crop, then drags splitters to `320,260,150` and hides
   Inspector/drawer. A second process must load the same layout and produce a
   byte-identical full BMP with seven entities and Player `3:1`.
5. **Shipped.** Studio 0.5.0 installed and signature-verified; installed
   Scene/Game/edit/layout captures are byte-identical to the local test
   captures. Website page and maturity row now show the Game Camera and
   persisted layout.

Limits: panels resize/hide but do not freely dock, float or reorder; the Scene
camera still lacks orbit/pan/zoom; the Game Camera is a tag convention without
FOV/near/far components or runtime input; history remains per-session. Next is
ENG-04.005, wiring the Scene camera through GUI events.

# 2026-11-27 — Working toolbar, menus and scene editing (ENG-04.006)

Starting point: Studio 0.5.0 had a painted transport strip, a static “Grid 1m”
label and a menu bar that looked interactive but had no hit tests. It was
possible to inspect and type transforms, but not to create an entity, drag one
in the viewport, or use File/Edit/GameObject commands.

1. **Tool state.** Added `ToolState` to the editor `App`: mode, snap, grid,
   open menu and in-flight drag. The World still owns only scene data. `Q`,
   `W`, `E` and `R` select the four tools; `G` toggles the grid; `Shift+S`
   toggles snapping. Escape closes a menu, cancels a drag or returns to Select
   instead of quitting; `⌘Q` is the quit path.
2. **Real toolbar.** Play, pause and step already had handlers; Select, Move,
   Rotate, Scale, Snap, Grid, Add, Dup and Del now do too. Move changes X/Z from
   the screen delta, Rotate composes a yaw quaternion around Y, and Scale applies
   a uniform factor. Snapping rounds to 0.5 m, 15° and 0.1 scale. Releasing a
   drag records one `EditCommand`, so Undo restores the pre-drag transform.
3. **Real menus.** File, Edit, Assets, GameObject, Component, Window and Help
   open dropdowns and execute the same command functions as the toolbar. New
   Scene creates a ground-only world; Reset Demo restores the seven-entity
   scene; GameObject creates cubes and cameras; Edit and the toolbar share
   Undo/Redo/Duplicate/Delete; Window toggles the three panels. Assets and
   Component report their missing systems rather than faking them.
4. **Scene editing.** Add spawns a tag-2 cube, selects it and switches to Move;
   Duplicate copies position/rotation/scale with a 0.6 m offset; Delete
   despawns and selects the first live entity. A new scene can therefore be
   built from the toolbar without editing Nova source.
5. **Acceptance.** `shell.sh` clicks the real toolbar and menu rectangles. It
   checks play/step, drags Player to `4.00, 1.40, 0.00`, undoes that drag,
   rotates 90°, scales to `1.20, 2.60, 1.20`, creates entity `7:1`, duplicates,
   deletes, toggles snap/grid, opens GameObject and Window menus, and compares
   a grid-off viewport crop. The existing edit/undo/redo, Game Camera and
   byte-identical layout-restart checks remain.
6. **Shipped.** Studio 0.6.0 installed and signature-verified. All six
   installed captures (Scene, Game, edit, layout, toolbar, Add) are
   byte-identical to the local acceptance captures. The website page and
   maturity row now show the toolbar and created cube.

Limits: the tools are drag-only with no gizmo handles, local/world toggle,
multi-select or grouped undo; menus are minimal with no keyboard navigation or
context menus; the Scene camera still lacks orbit/pan/zoom; there is no scene
save/load, asset pipeline, component registry, free docking or multi-window
editor.
