export const base = import.meta.env.BASE_URL

**Status: phase-0 vertical slice, macOS arm64.** Nova Engine Studio is the native editor shell for Nova Engine. It is not a Unity wrapper, an Electron app or a mock layout: hierarchy, resizable and hideable panels, Scene/Game views, toolbar commands, editable inspector and console all read the same live `World` value. The centre viewport is an offscreen Metal render composited into the same Nova GUI bitmap as the editor chrome.

Every panel is drawn by [nova-gui](../../libraries/gui/) from Nova code. The project is the first editor-facing slice of the engine, not a finished product.

## What is real

- **One World.** The hierarchy lists live entity slots and their generation handles. Selection, inspector fields, toolbar commands, play/pause/step and the console all read the same `world.nova` value. The demo has seven entities: ground, two crates, Player, Key Light, Pedestal and Game Camera.
- **A working toolbar and menus.** Play, pause and step run the fixed 1/60 s tick. Select, Move, Rotate and Scale are real viewport tools, with `Q`/`W`/`E`/`R` shortcuts and active states. Snap toggles 0.5 m / 15° / 0.1 scale, Grid toggles the 1 m overlay, and Add/Dup/Del create, duplicate or despawn real World entities. File, Edit, Assets, GameObject, Component, Window and Help open dropdowns and execute commands; unavailable asset and component systems report that instead of pretending.
- **Scene camera controls.** Right-drag orbits the editor camera around its target, `Shift`+right-drag pans in the screen plane, `Option`+left-drag orbits on a trackpad, and the scroll wheel zooms from 2.5 m to 40 m. The camera is editor-only state: the World and the Game Camera entity are untouched, and Game ignores Scene camera input. The viewport footer states the controls.
- **Viewport drag transforms with undo.** With Move, drag the selected entity in Scene to change X/Z. Rotate turns it around Y; Scale changes all three axes uniformly. Snapping is applied while dragging. Releasing records one before/after `EditCommand`, so the same Undo/Redo path restores a drag exactly like a typed inspector edit. `Esc` cancels the drag; it no longer quits the editor.
- **Editable transforms with undo.** Click Position, Rotation or Scale, type comma-separated decimal values and press Enter. The inspector parses them to Q16.16 and commits through the same `world_set_position/rotation/scale` APIs. A 16-entry editor-only command stack records before/after values; Undo/Redo buttons and ⌘Z/⇧⌘Z replay it. Invalid input keeps the field active, and a new edit truncates redo.
- **Persistent panel layout.** Drag the splitter beside Hierarchy, Inspector or the bottom drawer to resize it, or use the `Hier`/`Insp`/`Draw` chips in the menu bar to hide and restore it. The editor writes `layout.txt` under `~/Library/Application Support/Nova Engine Studio/`; a restart loads the same sizes and visibility before the first frame. Hiding a panel never clears the World or the selection.
- **A Metal viewport.** The Scene/Game centre is an offscreen Metal render, not a CPU wireframe. Studio builds one Q16.16 model-view-projection matrix per live entity and submits a bounded draw list to `runtime/metal.m`; the host renders depth-tested lit checker meshes with one directional light. The frame is read back at the display's backing scale and composited into the same sRGB bitmap as the panels, so `gui.save_png` captures the viewport and the editor together. It is an offscreen render, not an embedded `MTKView`.
- **Scene and Game Camera.** Scene uses an editable editor perspective with orbit, pan and zoom, and draws the grid, selected-player box and entity label. Game renders through the tagged `Game Camera` entity: its World position and rotation become the eye and look direction, the camera entity itself is hidden from its own view, and editor overlays stay off. Selecting the Game Camera and editing its transform changes Game immediately; moving the Scene camera never changes Game.
- **Keyboard controls.** `Space` plays or pauses, `S` advances one fixed tick, `Shift+S` toggles snapping, `G` toggles the grid, `Q`/`W`/`E`/`R` select the four tools, `Tab` cycles live entities, `Delete` despawns the selection, `⌘D` duplicates it, `⌘R` resets the demo and `⌘Q` quits. `Esc` closes a menu, cancels a drag or returns to Select.
- **A native shell.** The installer produces `Nova Engine Studio.app` with an icon and an ad-hoc signature. There is no web view, Electron or JavaScript runtime.

## Run it

Use the compiler built from the current sources; the checked-in stage-0 bootstrap predates the shell and Metal support.

```sh
# from the repository root
(cd examples/nova-tool && ../../bootstrap/nova build)
cd examples/scene-gui
../../examples/nova-tool/target/nova/nova-tool build
./target/nova/scene-gui
```

Install the signed local app:

```sh
cd examples/scene-gui
sh install-macos.sh
open "/Applications/Nova Engine Studio.app"
```

The bundle is ad-hoc signed, not Developer ID signed or notarized. On first launch macOS may require right-click → **Open**. The installer falls back to `~/Applications` when `/Applications` is not writable.

## Capture test

```sh
cd examples/scene-gui
sh tests/shell.sh
```

The test captures both tabs at 2880×1800, checks the traffic-light row through `NOVA_GUI_TRACE`, enters Game through the same mouse-down hit test as the window, and samples 13 pixels: panel surfaces, both active-tab states, the selected hierarchy row, the Metal clear colour, two checker-texture colours, the inspector and the drawer. It compares Scene and Game viewport crops, then selects the Game Camera, moves it through the inspector and requires the Game viewport to change.

The toolbar and menu checks click the real rectangles through `handle_mouse_down`. Play and Step must change state; Move, Rotate and Scale drags must change the selected transform and record one undo command; Add, Duplicate and Delete must change the live entity count and selection; Snap and Grid must toggle; the GameObject menu must create a cube; the Window menu must hide the inspector. Grid-off must change the viewport crop. A painted button that lost its hit test fails the suite.

Scene camera acceptance synthesizes right-drag orbit `80,-20`, shift-right-drag pan `40,10` and scroll zoom `120`. It requires the eye, target and distance to change, compares all three Scene crops against the base, and runs the same orbit in Game where the Game crop must stay byte-identical.

Inspector editing still focuses Position through the row hit test, sends `2.5, 1.4, 1`, and captures edit, undo and redo; the output must step `history=1/1 → 0/1 → 1/1`, undo must restore the base viewport and redo the edit. Layout acceptance uses the real splitter hit test and visibility chips, then launches a second process from the same file and requires a byte-identical full capture with `layout=320,260,150 h=1 i=0 d=0`. Finally it runs five live frames through `NOVA_SCENE_FRAMES` and requires `live=stopped frames=5 viewport=metal`.

The title strip calls `gui.place_traffic_lights(14)` and reserves 84 points on the left, so AppKit's close/minimize/zoom buttons do not overlap the title or menu. AppKit's own event delivery is still a manual check; the capture test verifies the handler below it.

## Honest gaps

- **Scene camera controls are mouse-only.** Orbit, pan and zoom work in Scene, but there is no focus-selected command, camera preset, keyboard fly or persisted camera state. The Game Camera is an editable World entity, but it still has no runtime player input or FOV/near/far component.
- **Panels resize and hide, but do not freely dock.** Hierarchy, Inspector and the drawer are three fixed regions with persisted sizes and visibility. There is no floating, tabbed or reordered panel system, and no multi-window editor.
- **The tools are drag tools, not gizmos.** There is no axis handle, rotation ring, scale handle, local/world toggle, multi-select or grouped command. A drag edits the whole Position, Rotation or Scale vector, and history is per-session.
- **The menus are minimal.** Assets and Component open, but the asset pipeline and component registry do not exist yet. There is no menu keyboard navigation, context menu, prefab or scene save/load.
- **Game is a camera view, not a build.** It uses the Game Camera entity and hides editor overlays, but it does not package a player, simulate separate runtime input or isolate play state.
- **No scene save/load.** The seven-entity demo world is created in code each launch; only the editor panel layout is persisted.
- **No GPU timing or advanced renderer.** The viewport has one directional light, one texture slot, no MSAA, shadows, normal mapping, mipmaps or asset pipeline.
- **macOS arm64 only.** The host uses AppKit, CoreGraphics, CoreText and Metal.
