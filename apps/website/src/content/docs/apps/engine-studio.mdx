export const base = import.meta.env.BASE_URL

**Status: phase-0 vertical slice, macOS arm64.** Nova Engine Studio is the native editor shell for Nova Engine. It is not a Unity wrapper, an Electron app or a mock layout: hierarchy, resizable and hideable panels, Scene/Game views, editable inspector and console all read the same live `World` value. The centre viewport is an offscreen Metal render composited into the same Nova GUI bitmap as the editor chrome.

Every panel is drawn by [nova-gui](../../libraries/gui/) from Nova code. The project is the first editor-facing slice of the engine, not a finished product.

## What is real

- **One World.** The hierarchy lists live entity slots and their generation handles. Selection, inspector fields, play/pause/step and the console all read the same `world.nova` value. The demo has seven entities: ground, two crates, Player, Key Light, Pedestal and Game Camera.
- **Editable transforms with undo.** Click Position, Rotation or Scale, type comma-separated decimal values and press Enter. The inspector parses them to Q16.16 and commits through the same `world_set_position/rotation/scale` APIs. A 16-entry editor-only command stack records before/after values; Undo/Redo buttons and ⌘Z/⇧⌘Z replay it. Invalid input keeps the field active, and a new edit truncates redo. The runtime owns no undo state.
- **Persistent panel layout.** Drag the splitter beside Hierarchy, Inspector or the bottom drawer to resize it, or use the `Hier`/`Insp`/`Draw` chips in the menu bar to hide and restore it. The editor writes `layout.txt` under `~/Library/Application Support/Nova Engine Studio/`; a restart loads the same sizes and visibility before the first frame. Hiding a panel never clears the World or the selection.
- **A Metal viewport.** The Scene/Game centre is an offscreen Metal render, not a CPU wireframe. Studio builds one Q16.16 model-view-projection matrix per live entity and submits a bounded draw list to `runtime/metal.m`; the host renders depth-tested lit checker meshes with one directional light. The frame is read back at the display's backing scale and composited into the same sRGB bitmap as the panels, so `gui.save_png` captures the viewport and the editor together. It is an offscreen render, not an embedded `MTKView`.
- **Scene and Game Camera.** Scene uses a fixed editor perspective and draws the grid, selected-player box and entity label. Game renders through the tagged `Game Camera` entity: its World position and rotation become the eye and look direction, the camera entity itself is hidden from its own view, and editor overlays stay off. Selecting the Game Camera and editing its transform changes Game immediately.
- **Real time controls.** `Space` plays or pauses, `S` advances one fixed 1/60 s tick, `Tab` cycles live entities, `Delete` despawns the selection, and `R` resets the demo world. Clicking a transform row focuses it; Enter applies and Escape cancels.
- **A native shell.** The installer produces `Nova Engine Studio.app` with an icon and an ad-hoc signature. There is no web view, Electron or JavaScript runtime.

## Run it

Use the compiler built from the current sources; the checked-in stage-0 bootstrap predates the shell and Metal support.

```sh
# from the repository root
(cd examples/nova-tool && ../../bootstrap/nova build)
cd examples/scene-gui
../../examples/nova-tool/target/nova/nova-tool build
./target/nova/scene-gui
```

Install the signed local app:

```sh
cd examples/scene-gui
sh install-macos.sh
open "/Applications/Nova Engine Studio.app"
```

The bundle is ad-hoc signed, not Developer ID signed or notarized. On first launch macOS may require right-click → **Open**. The installer falls back to `~/Applications` when `/Applications` is not writable.

## Capture test

```sh
cd examples/scene-gui
sh tests/shell.sh
```

The test captures both tabs at 2880×1800, checks the traffic-light row through `NOVA_GUI_TRACE`, enters Game through the same mouse-down hit test as the window, and samples 13 pixels: panel surfaces, both active-tab states, the selected hierarchy row, the Metal clear colour, two checker-texture colours, the inspector and the drawer. It compares Scene and Game viewport crops, then selects the Game Camera, moves it through the inspector and requires the Game viewport to change. It also focuses Position through the inspector row hit test, sends `2.5, 1.4, 1`, and captures edit, undo and redo; the output must step `history=1/1 → 0/1 → 1/1`, undo must restore the base viewport and redo the edit. Layout acceptance uses the real splitter hit test and visibility chips, then launches a second process from the same file and requires a byte-identical full capture with `layout=320,260,150 h=1 i=0 d=0`. Finally it runs five live frames through `NOVA_SCENE_FRAMES` and requires `live=stopped frames=5 viewport=metal`. All captures are left in `target/` for review.

The title strip calls `gui.place_traffic_lights(14)` and reserves 84 points on the left, so AppKit's close/minimize/zoom buttons do not overlap the title or menu. AppKit's own event delivery is still a manual check; the capture test verifies the handler below it.

## Honest gaps

- **The Scene camera is fixed.** Studio's editor perspective does not orbit, pan or zoom yet. The Game Camera is an editable World entity, but it has no runtime controls or player input; orbit/pan/zoom remain verified only in `examples/metal-lab`.
- **Panels resize and hide, but do not freely dock.** Hierarchy, Inspector and the drawer are three fixed regions with persisted sizes and visibility. There is no floating, tabbed or reordered panel system, and no multi-window editor.
- **History is per-session and single-field.** The inspector edits one whole Position, Rotation or Scale vector at a time. There is no multi-select, grouped command, gizmo, persisted undo, prefab or scene save/load. Add Component still reports that no component types are registered yet.
- **Game is a camera view, not a build.** It uses the Game Camera entity and hides editor overlays, but it does not package a player, simulate separate runtime input or isolate play state.
- **No scene save/load.** The seven-entity demo world is created in code each launch; only the editor panel layout is persisted.
- **No GPU timing or advanced renderer.** The viewport has one directional light, one texture slot, no MSAA, shadows, normal mapping, mipmaps or asset pipeline.
- **macOS arm64 only.** The host uses AppKit, CoreGraphics, CoreText and Metal.
